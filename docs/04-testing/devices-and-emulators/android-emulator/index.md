# Android 模拟器

安装见 [安装](./installation.md)，命令见 [常用命令](./commands.md)。

## 它是什么

完整的 Android 系统镜像跑在电脑上——真内核、真系统服务、真应用框架，只有硬件是虚拟的。

对比 iOS Simulator：后者并不运行 iOS，而是把 app 编译成 Mac 原生程序跑在 macOS 上，
性能与真实度都不可参考。所以模拟器上跑通的功能绝大多数在真机上也成立，
不成立的那些见 [必须上真机的](../index.md#必须上真机的)。

AVD 可随意创建销毁，一台机器上并存十几个（不同 API level、尺寸、密度），
随时 wipe 回出厂状态——真机做不到。

## 开发时用

- **日常循环**：改代码 → 装包或热重载 → 看效果，不需要真机在手边
- **多版本适配**：API 24 / 31 / 36 各跑一遍。真机凑不齐这些版本，这是模拟器**不可替代**的用途
- **多屏幕适配**：尺寸、密度、刘海。布局问题大多在这一步暴露，而不是等到真机
- **重测首次启动**：权限弹窗、引导页、登录态只在首装时出现，`adb shell pm clear <package>` 即可重来
- **切语言与时区**：i18n、日期格式、RTL 布局，改动即时生效
- **深链唤起**：`adb shell am start -a android.intent.action.VIEW -d "myapp://path"`

## 测试时用

单元测试和 Widget 测试**不需要**模拟器，它们跑在 JVM / Dart VM 里；
集成测试与 UI 测试才需要。

模拟器的价值是可脚本化、可批量、免费：多实例并行缩短反馈、每个用例前 wipe 保证互不污染、
能直接跑在 CI 上而不用有人插着真机。CI 里 headless 启动：

```bash
emulator -avd <name> -no-window -no-audio -no-boot-anim -wipe-data
```

所以自动化测试基本都在模拟器上跑，真机留给人工抽查。

## 扩展控制面板

模拟器窗口右侧工具条的 `...` 打开，能模拟真机上难以复现的条件：GPS 位置与移动路线、
网络限速与丢包、电量与充电状态、加速度计/陀螺仪/光线、来电与短信、屏幕旋转与折叠屏展开。

这是 Android Emulator 相对 iOS Simulator 的一个实际优势。
